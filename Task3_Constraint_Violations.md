# Task 3: Constraint Violations - ARLCCS

## Violation Scenarios

| Constraint ID | Formal Constraint | Violation State | Explanation (What went wrong & detection method) |
|---|---|---|---|
| C1 | TrainDetected → BarrierLowered within 2 seconds | TrainDetected=TRUE, BarrierLowered=FALSE, DescentTimeElapsed=3.5s | Train detected but barrier descent took 3.5 seconds instead of required maximum 2 seconds. Detected by: monitoring DescentTimeElapsed timer and comparing to threshold; barrier position sensor still reporting "raised" state. System should trigger descent timeout alarm. |
| C2 | TrainDetected → BarrierLowered | TrainDetected=TRUE, BarrierLowered=FALSE, BarrierDescentInProgress=FALSE | Train present on crossing but barrier remains raised and no descent is in progress. Possible causes: descent command never issued, motor failure, or sensor malfunction. Detected by: continuous polling of train detection and barrier position; alert when train detected but barrier not lowered. |
| C3 | (¬TrainDetected ∧ TrainDeparted>5) → Barrier can raise | TrainDetected=FALSE, TrainDeparted=3s, BarrierLowered=TRUE, BarrierDescentInProgress=FALSE | Train has departed but only 3 seconds have elapsed instead of required 5-second safety delay. Barrier begins raising prematurely. Detected by: TrainDeparted counter not meeting 5-second threshold before raising logic executes; violation caught by temporal constraint validation. |
| C4 | TrainDetected → WarningLightsActive ≥10s before descent | TrainDetected=TRUE, WarningLightsActive=FALSE, BarrierDescentInProgress=TRUE, DescentTimeElapsed=2s | Train detected and barrier descent initiated, but warning lights never activated or activated simultaneously with descent instead of 10 seconds prior. Detected by: checking WarningLightsActive state when TrainDetected becomes TRUE; comparing light activation time to descent initiation time. |
| C5 | BarrierDescentInProgress → WarningBellActive until DescentCompleted | BarrierDescentInProgress=TRUE, WarningBellActive=FALSE, DescentCompleted=FALSE | Barrier is descending but warning bell is not active, depriving pedestrians and inattentive drivers of audible warning. Detected by: monitoring WarningBellActive flag during descent phase; alert if bell is disabled or malfunctions while descent ongoing. |
| C6 | SensorFault → (BarrierLowered ∧ WarningLightsActive ∧ WarningBellActive) | SensorFault=TRUE, BarrierLowered=FALSE, WarningLightsActive=TRUE, WarningBellActive=TRUE | Sensor fault detected (e.g., train detection sensor malfunction) but barrier was not lowered; only lights and bell activated. Safe-fail requires ALL defensive actions. Detected by: explicit SensorFault flag raised; verifying that SystemInSafeState (all three conditions met) is enforced when any SensorFault detected. |
| C7 | CommunicationLoss → (BarrierDescentInProgress ∧ WarningLightsActive ∧ WarningBellActive) | CommunicationLoss=TRUE, BarrierDescentInProgress=TRUE, WarningLightsActive=FALSE, WarningBellActive=TRUE | Communication lost with light controller subsystem; barrier descent and bell triggered but warning lights failed to activate. Incomplete fail-safe response. Detected by: heartbeat/acknowledgment timeouts on light controller channel; verifying all three fail-safe actions complete even if one subsystem unreachable. |
| C8 | EmergencyStop → (BarrierDescentInProgress ∧ WarningLightsActive ∧ WarningBellActive ∧ SystemInSafeState) | EmergencyStop=TRUE, BarrierDescentInProgress=TRUE, WarningLightsActive=TRUE, WarningBellActive=TRUE, SystemInSafeState=FALSE | Emergency stop button pressed, barrier descending and warnings active, but SystemInSafeState=FALSE because position sensor reports barrier still partially raised (BarrierLowered=FALSE). Descent incomplete or sensor error. Detected by: SystemInSafeState boolean failing verification; position sensor confirmation required; if descent timeout occurs during emergency stop, trigger alarm and retry descent sequence. |
